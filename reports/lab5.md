# 功能实现
* ProcessControlBlockInner中新增了Resource对象和是否开启死锁判断的标志；
* Resource对象维护了4个字段：available_vec可用的资源、allocation_vec已分配资源、need_vec等待分配的资源、request_vec线程id；
* Resource在请求锁的时候，如果现有资源足够直接将available_vec中的资源分配给allocation_vec，否则往need_vec写入资源等待，按算法判断是否系统处于安全状态；
* Resource在释放锁的时候，将资源还给available_vec，同时更新need_vec，给等待资源的线程提供资源;

# 简答
* 在我们的多线程实现中，当主线程 (即 0 号线程) 退出时，视为整个进程退出， 此时需要结束该进程管理的所有线程并回收其资源。 - 需要回收的资源有哪些？ - 其他线程的 TaskControlBlock 可能在哪些位置被引用，分别是否需要回收，为什么？

* * 需要回收当前线程和子线程的TaskUserRes包括user stack trap_cx tid等；其他线程的 TaskControlBlock可能在锁、信号量等跨线程变量中使用，不需要回收，因为线程都会被TASK_MANAGER统一管理，能够正确处理已经被标记回收的线程；

* 对比以下两种 Mutex 中的实现，二者有什么区别？这些区别可能会导致什么问题？

* * mutex1在lock中增加了loop循环，可能会导致task重复放入wait_queue
